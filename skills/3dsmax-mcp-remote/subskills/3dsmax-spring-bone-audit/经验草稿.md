# 3ds Max 弹簧/柔体骨骼审计经验草稿

> 本文件为待人工审核草稿，不自动修改 `SKILL.md`。

## 一、目的与适用范围

本经验用于审计 3ds Max 场景中的角色辅助骨骼，确定哪些骨骼链应提交给弹簧/柔体解算工具。

审计必须基于完整对象类型、父子层级、命名、角色关联和必要的视口证据，不得只看当前可见网格，也不得只根据父级名称或骨骼编号作判断。

本经验不改变以下既有要求：

- 排除 Biped 主体骨骼（例如 `Bip01...`），不得把它们列为柔体入口；
- 当前没有模型或蒙皮权重的角色辅助骨骼仍须保留在审计和换肤候选记录中；
- 同一条连续骨骼链只输出一个入口，子级不重复输出；
- 非骨骼挂点、插槽和中间节点须记录为路径上下文，但柔体入口必须指向真实辅助骨骼。

## 二、核心概念定义

### 1. 辅助骨骼树根

用于组织整棵辅助骨骼树的上游节点，例如总根骨骼、骨架根节点或插槽/挂点节点。

辅助骨骼树根只作为层级路径上下文，通常不作为柔体计算入口。名称中包含 `root` 只能作为判断线索，不能单独作为排除或纳入依据，必须结合子级结构确认。

### 2. 分支汇聚节点

拥有两个或更多明显延伸子分支的节点。它承担骨骼树的组织、分流或汇聚作用，不应直接作为某一条柔体链的入口。

遇到分支汇聚节点时，必须继续检查每个子分支，并分别寻找每条分支的第一节真实辅助骨骼。

### 3. 柔体链首/柔体计算入口

从总根、Biped 父级、挂点/插槽或分支汇聚节点进入某条连续辅助骨骼链后，该分支中最上游的第一节真实辅助骨骼。

柔体计算入口不是：

- 整棵辅助骨骼树的总根；
- 拥有多个长分支的分支汇聚节点；
- 非骨骼挂点或插槽；
- 仅有自身一节、没有连续子骨骼的单节骨骼（除非具体柔体工具明确允许单骨骼控制器）。

### 4. 连续链子级

柔体链首之后沿单一路径延伸的子骨骼。它们属于同一条柔体链，由解算工具从链首开始自动处理，不得再次列为独立入口。

### 5. 单节候选

没有任何连续子骨骼的真实辅助骨骼。单节骨骼不能仅因位于角色辅助骨骼树中就自动判定为需要柔体计算。

单节骨骼仍须保留在完整审计记录和后续换肤候选中；如果柔体工具要求至少两节连续骨骼，则单节骨骼不列入最终柔体入口列表，而应放入“单节/待确认候选”。

## 三、链首判定的关键经验

1. **“最上游辅助骨骼”不等于“柔体计算入口”**。必须先识别总根、挂点、分支汇聚节点和真实辅助骨骼，再确定柔体链首。
2. 名称包含 `root` 的节点通常是骨架根或挂点上下文，但不能只凭名称排除；必须继续读取其完整子级结构。
3. 一个节点如果拥有两个或更多明显延伸的骨骼分支，通常承担根节点或分支汇聚作用，应排除该节点本身，并分别检查各子分支。
4. “明显延伸分支”至少应有连续子骨骼证据。只有自身一节的子节点不能直接视为长链；应标记为单节候选并说明是否需要人工确认。
5. 从分支汇聚节点进入某条子分支时，该分支的第一节真实辅助骨骼才是候选入口；分支后续连续子级不再单独输出。
6. 单节骨骼如 `Bone_qb_01`，即使属于角色辅助骨骼树，也不应自动列入需要柔体计算的长链入口；但不能从审计和换肤记录中删除。
7. 如果工具明确要求柔体链至少包含两节骨骼，入口必须至少拥有一个连续子骨骼；单节节点只能列为单节/待确认候选。
8. 不能只按“父级不是辅助骨骼”判断链首。还必须判断该节点是否为总根、分支汇聚节点、挂点/插槽、单节节点或真正的连续链首。
9. 当前没有可见模型或蒙皮权重只能说明当前不可见或未确认绑定，不能据此排除角色辅助骨骼；模型、骨骼和层级必须结合判断。

## 四、推荐判定流程

1. 完整查询目标集合中的所有对象，确认骨骼对象类型；不能只检查已知编号或当前可见网格。
2. 枚举全部真实辅助骨骼，并读取每根骨骼及相关非骨骼节点的父子层级。
3. 排除 Biped 主体骨骼，但保留其下挂接的非 Biped 辅助骨骼作为审计对象。
4. 建立完整骨骼树，识别总根、挂点/插槽、分支汇聚节点、连续链和单节节点。
5. 从总根或上游挂点开始递归：
   - 总根/插槽/挂点：保留为路径上下文，不直接作为入口；
   - 多分支汇聚节点：不作为入口，继续检查每个子分支；
   - 子分支的第一节真实辅助骨骼：作为该分支的候选柔体入口；
   - 候选入口后只有一个连续子级的节点：视为同一条链的后续，不重复输出；
   - 候选节点没有连续子骨骼：标记为单节候选，不默认列入最终柔体入口；
   - 若某个后续节点再次出现多个长分支：将其识别为新的分支汇聚节点，继续拆分并记录路径。
6. 对脱离 Biped 层级的独立骨骼链，结合命名、位置/变换、邻近节点和角色关联判断；证据不足时列为待确认候选，不得仅因没有 Biped 父级而排除。
7. 对每个候选入口进行场景选择和视口交叉核验。截图只用于核验位置、角色关联和挂点，不得替代对象类型及层级查询。
8. 每条连续柔体链只保留一个入口，去除其所有重复子级。
9. 输出最终柔体入口、单节/待确认候选、完整骨骼链、挂点路径、视觉核验、排除项和检查限制。

## 五、判定示例

对于如下局部结构：

```text
Bone_qb_root
└─ Bone_qb_02
   ├─ Bone_qb_33_r
   │  ├─ Bone_qb_34_r -> ...
   │  └─ Bone_qb_41_r -> ...
   ├─ Bone_qb_12
   │  ├─ Bone_qb_13 -> ...
   │  └─ Bone_qb_20 -> ...
   └─ Bone_qb_01
```

应判定为：

```text
排除为总根/分支汇聚节点：
Bone_qb_root
Bone_qb_02
Bone_qb_33_r
Bone_qb_12

长链柔体入口：
Bone_qb_34_r
Bone_qb_41_r
Bone_qb_13
Bone_qb_20

单节/待确认候选：
Bone_qb_01
```

路径应记录为：

```text
Bone_qb_root -> Bone_qb_02 -> Bone_qb_33_r -> Bone_qb_34_r
Bone_qb_root -> Bone_qb_02 -> Bone_qb_33_r -> Bone_qb_41_r
Bone_qb_root -> Bone_qb_02 -> Bone_qb_12 -> Bone_qb_13
Bone_qb_root -> Bone_qb_02 -> Bone_qb_12 -> Bone_qb_20
Bone_qb_root -> Bone_qb_02 -> Bone_qb_01
```

注意：以上为局部示意，不代表 `Bone_qb_02` 的全部子分支。实际审计时必须继续检查未在示例中列出的所有子级。

## 六、典型场景的正确处理

### 场景 A：总根下只有一条连续链

```text
Root -> Bone_A -> Bone_B -> Bone_C
```

若 `Root` 是总根或挂点，则 `Bone_A` 是柔体链首；`Bone_B`、`Bone_C` 不重复输出。

### 场景 B：节点下有两条或更多长分支

```text
Root -> Bone_Root
          ├─ Bone_A -> Bone_A1 -> ...
          └─ Bone_B -> Bone_B1 -> ...
```

`Bone_Root` 是分支汇聚节点，不作为入口；应输出 `Bone_A` 和 `Bone_B`。

### 场景 C：节点下只有一个单节子节点

```text
Root -> Bone_A
```

`Bone_A` 是单节候选。保留在审计和换肤记录中，但若柔体工具要求连续骨骼链，则不列入最终柔体入口。

### 场景 D：非骨骼挂点位于入口上方

```text
Bip01 Spine -> v_hair_socket -> Bone_A -> Bone_B
```

入口为 `Bone_A`，而不是 `v_hair_socket`。输出时记录完整挂点路径。

### 场景 E：独立于 Biped 的辅助链

```text
Bone_A -> Bone_B -> Bone_C
```

不能仅因没有 Biped 父级而排除。应结合命名、位置、邻近对象和角色关联判断；证据不足时列为待确认候选。

## 七、输出时必须区分的结果类别

### 最终柔体入口

具有连续子骨骼、确认属于角色辅助骨骼、且不是总根/汇聚节点/挂点的链首。

### 单节/待确认候选

属于角色辅助骨骼，但没有连续子骨骼，或柔体工具是否允许单骨骼控制器尚未确认。

### 排除节点

总根、分支汇聚节点、Biped 主体、非骨骼挂点/插槽、无角色关联的独立骨骼，以及非骨骼对象。

排除节点仍应在完整层级和排除说明中记录，不能从查询结果中隐去。

## 八、避免的错误

- 不要把辅助骨骼树总根直接作为柔体入口。
- 不要把拥有多个长分支的分支汇聚节点作为入口。
- 不要把单节骨骼自动当作柔体链。
- 不要把非骨骼挂点/插槽当作柔体入口。
- 不要只按“父级不是辅助骨骼”这一条规则输出。
- 不要只检查当前可见网格或已发现的骨骼编号。
- 不要因当前没有模型或蒙皮权重就删除辅助骨骼候选。
- 不要把同一条连续链的子级重复列为入口。
- 不要让视口截图结论覆盖对象类型和完整层级查询。
- 视角切换失败、截图重复、层级不完整或角色关联证据不足时，必须如实记录限制和不确定性。

## 九、MAXMCP_URL 与 3dsMax-MCP 服务器连接检查

执行场景审计前，必须先检查当前环境是否配置了 `MAXMCP_URL`，并通过该地址访问 3dsMax-MCP 服务器。不得猜测、硬编码或自行替换 MCP 地址，例如不得直接假设使用 `localhost`。

### 1. 检查环境变量

优先读取当前环境中的 `MAXMCP_URL`：

```bash
if [ -n "${MAXMCP_URL:-}" ]; then
  printf 'MAXMCP_URL is set: %s\\n' "$MAXMCP_URL"
else
  printf '%s\\n' 'MAXMCP_URL is not set'
fi
```

如果 `MAXMCP_URL` 未设置或为空：

- 不得猜测服务器地址；
- 不得直接访问 `127.0.0.1`、`localhost` 或其他默认地址；
- 应停止实际场景审计，并明确报告缺少 MCP 地址；
- 只有在用户补充配置或重新开启已配置 MCP 的会话后，才能继续。

### 2. 检查在线 Max 实例

使用已确认的 `MAXMCP_URL` 调用 3dsMax-MCP 的实例查询能力，优先使用 `list_instances` 或远程 Skill 提供的等效工具，确认：

- 服务器在线且可以响应；
- 存在可用的 3ds Max 实例；
- 目标实例处于空闲状态，或当前会话已经持有该实例；
- 实例名称、主机、端口、在线状态和 busy 状态均有实际返回。

示例命令：

```bash
python /root/.claude/skills/3dsmax-mcp-remote/scripts/list_online_instances.py \\
  --url "$MAXMCP_URL"
```

若没有在线或空闲实例：

- 不得等待、猜测或切换到未确认的实例；
- 应如实说明当前无法执行审计；
- 不得输出虚构的骨骼结果。

### 3. 选择目标实例

从实际返回的在线实例中选择目标 Max 实例，并记录实例名称，例如 `max-8765`。通过 3dsMax-MCP 的实例选择能力绑定目标实例时：

- 使用实际返回的实例名称或 PID；
- 不得手写未查询到的实例名或 PID；
- 不得因一个实例选择失败就默默切换到另一个实例；
- 选择结果必须确认 `acquired`、在线状态或等效绑定状态。

### 4. 验证 MCP 工具面

连接后应确认服务器实际提供了审计所需的工具，不得只依据文档假设工具一定存在。至少应确认下列能力中的对应工具：

- 查询可见/未隐藏对象，例如 `query_scene(action="unhidden_objects")`；
- 查询全部未隐藏网格和骨骼，例如 `get_unhidden_meshes_bones`；
- 查询对象层级，例如 `get_hierarchy`；
- 查询对象属性或对象类型，例如 `get_object_properties`；
- 必要时选择对象并捕获视口，例如 `select_objects`、`capture_viewport`。

如果服务器使用渐进式工具面而不是直接暴露操作工具，应先通过实际提供的 `list_toolsets`、`describe_toolset` 和 `call_tool` 发现并调用对应能力。遇到 `Unknown tool` 时，应重新查询实际工具列表，不得持续猜测工具名。

### 5. 执行审计与截图

完成环境、服务器和实例验证后，才可读取 `UnhiddenObjects`、骨骼层级和对象属性。需要视觉核验时：

- 使用已绑定或已确认的实例执行截图；
- 截图是交叉证据，不替代层级和对象类型查询；
- 不得为了截图在 busy 实例上额外排队获取长时间租约；
- 视角切换失败或多张截图内容重复时，必须在结果中说明；
- 不得把未成功获得的视角描述为已完成核验。

### 6. 连接失败时的输出要求

如出现以下任一情况，必须停止场景结论输出并记录限制：

- `MAXMCP_URL` 未配置；
- MCP 服务器无法连接或返回错误；
- 没有在线/空闲 Max 实例；
- 工具面不包含必要的场景查询能力；
- 实例选择或绑定状态未确认；
- 层级查询返回不完整或无法确认对象类型。

连接失败时只能报告检查状态和失败原因，不能根据截图、文件名、历史结果或经验猜测当前场景的骨骼列表。
