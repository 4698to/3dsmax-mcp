# 3ds Max 弹簧骨骼审计

## 目标

检查当前 3ds Max 场景，在【目标集合】找出角色身上所有应提交给弹簧/柔体解算工具的辅助骨骼链首。只读检查，不修改场景。

### 目标集合

- 所有可见(未隐藏)的对象集合，isHidden == false 
- 所有对象集合，objects

## 强制规则

1. 排除所有 Biped 主体骨骼（`Bip01...`），不得把它们列入解算入口。
2. 只要是角色身上的Bone骨骼（biped骨架树下的骨骼对象），即使骨骼位置处没有可见mesh ，没有蒙皮权重，也必须纳入检查；后期换肤可能使用这些骨骼。
3. 每条骨骼链只输出第一节/根部骨骼。子级骨骼由解算工具自动处理，不得重复列出。
4. 解算入口不要求直接挂在 Biped 骨骼下：辅助骨骼链可能直接挂在 Biped 下、经由一个或多个中间挂点/插槽层连接，也可能是脱离 Biped 层级的独立骨骼链。不得仅因没有 Biped 父级或不在 Biped 子树中，就忽略看起来属于角色的辅助骨骼。
5. 排除挂在 `* L Hand` 或 `* R Hand` 手掌骨骼下的全部子骨骼链。手掌骨骼下的子骨骼按项目约定属于手指骨骼，不提交给弹簧/柔体解算工具。审计时仍须读取并记录这些链的层级，但不得将其链首或子级写入最终解算入口列表与完整解算链；排除项中须注明“手掌下手指骨骼”。
6. 链首定义为每条辅助骨骼链中最上游的真实辅助骨骼：其父级不是同一条辅助骨骼链中的真实辅助骨骼。父级可以是 Biped 骨骼、中间挂点/插槽（v_ 命名前缀对象）、或无父级。若入口前存在非骨骼挂点/插槽层，应把该层作为链路上下文记录，但解算入口仍应指向真实骨骼；若无法确定非骨骼节点是否为挂点/插槽或辅助骨骼是否属于角色，标注不确定性，不要默默排除。
7. 模型不存在时只能判定为当前不可见，不能据此推断场景中不存在角色部件；模型与骨骼必须结合判断。模型、骨骼和截图只能作为辅助证据，仍应结合完整节点层级、对象类型、命名及角色关联信息判断；不得把“直接父级为 Biped”当作唯一入口判据。
8. 名称中包含 `root` 的骨骼通常是骨架根节点或插槽/挂点等中间层，不能仅因名称带有 `root` 就认定它是柔体解算入口。应继续检查其子级：若该节点承担骨架根节点或插槽挂点作用，应排除该节点本身，并沿子级查找真正需要解算的辅助骨骼链首。若该节点有两个或更多明显延伸的骨骼链子级，视为根节点的佐证，排除该节点作为入口，并分别检查各子链；最终只列出符合解算条件的子链首。此命名规则仅作判断线索，必须结合对象类型、完整层级及角色关联核实。

## 必须执行的流程

1. 检查已配置的 3dsmax-mcp 服务和实例是否在线、空闲。使用现有 MCP 配置的地址，不得猜测或硬编码 localhost。
2. 需要了解角色外观时，可捕获正面、背面、左侧、右侧视口截图。若视角切换失败或截图重复，必须明确说明，不能假装已经获得不同视角。
3. 查询场景中的全部骨骼对象，确认对象类型并识别真实的辅助骨骼。`BoneGeometry` 和 `Bone##` 可以作为候选，但不能假设编号连续或只检查已知编号。
4. 读取每根骨骼及相关中间节点的父子层级，建立完整的辅助骨骼链与挂点/插槽路径。
5. 结合完整层级与节点信息，识别角色辅助骨骼链；同时检查直接挂在 Biped 下、经中间挂点/插槽连接，以及脱离 Biped 层级的骨骼链。对独立链应结合命名、位置/变换、邻近层级及角色关联判断；证据不足时列为待确认候选并说明依据，不得仅凭层级位置排除。
6. 对候选链首进行场景选择并截图，使用视觉信息交叉核验其在角色上的位置和归属，辅助区分角色辅助骨骼与无关对象、发现中间挂点/插槽层。选择与截图仅用于交叉核验，不能替代场景查询得到的对象类型和层级关系；隐藏、重叠或未绑定模型的骨骼可能无法从截图辨认，单凭“看起来在角色某处”不足以确认归属。若截图与查询信息不一致，记录差异及不确定性，不得以视觉结论覆盖层级查询。
7. 对每条链找到最上游真实辅助骨骼作为解算入口；如入口上方有非骨骼挂点/插槽，记录完整路径。去重：同一条链只保留一个入口，子级不单独输出。
8. 输出最终链首列表、每条完整链及其挂点路径、视觉交叉核验结果、排除的 Biped 主体骨骼类别和查询限制。

## 安全的层级读取方式

优先使用专用 MCP 场景查询工具。没有专用工具时，才使用只读 MAXScript

禁止为了读取层级而启用不安全 Python、修改 safe mode、修改场景设置或写入场景。

## 链首判定示例

如果查询结果为：

```text
Bone05 <- Bip01 Pelvis
Bone06 <- Bone05
Bone07 <- Bone06
Bone08 <- Bone07
```

只输出：

```text
Bone05
```

不能输出 `Bone06`、`Bone07`、`Bone08` 作为独立解算入口。

如果查询结果为：

```text
Bone37 <- Bip01 Spine2
Bone38 <- Bone37
Bone39 <- Bone38
```

只输出：

```text
Bone37
```

## 输出格式

```text
弹簧/柔体解算入口骨骼（每条链只列第一节）：
Bone...

完整骨骼链：
BoneRoot -> child -> child -> ...

挂点/插槽路径：
<入口骨骼> 上方经 <挂点A> -> <挂点B> 连接至 <Biped 骨骼>；无中间层则注明直接挂接或无父级

视觉交叉核验结果：
- <骨骼名>: 与查询层级一致 / 不一致（记录差异与不确定性）


检查限制：
如实说明 MCP 查询失败、视角切换失败、节点信息不完整等情况；关联证据不足的独立链列为待确认候选并附依据。

```


##  链首判定的关键经验

1. **“最上游辅助骨骼”不等于“柔体计算入口”**。先找到辅助骨骼树的上游节点，再判断该节点是否只是总根、分支汇聚节点或插槽层；不能把整棵树的总入口直接当作柔体入口。
2. 名称包含 `root` 的节点通常只是总根或挂点上下文，应继续检查其子级，不能仅凭名称判断。
3. 一个节点如果拥有两个或更多明显延伸的长骨骼分支，通常承担根节点/分支汇聚作用，应排除该节点本身，并分别从每条长分支的第一节真实辅助骨骼开始输出。
4. 例如：
   - 下有多条长分支，应排除 ；
5. 单节骨骼不能仅因位于辅助骨骼树中就判定为需要柔体计算。只有自身一节、没有延伸子链，应标为“单节/待确认”，默认不列入需要柔体计算的长链入口。


## 推荐判定流程

1. 完整读取所有骨骼对象和父子层级，先建立树，不要根据对象枚举顺序或编号猜测链路。
2. 从总根开始向下递归：
   - 总根/插槽/挂点：只保留为路径上下文；
   - 多分支汇聚骨骼：不作为入口，继续递归检查每个子分支；
   - 只有一个延伸子级的普通链节：沿链继续，但最终入口应回溯到该连续链的第一节；
   - 长链第一节：作为候选柔体入口；
   - 单节无延伸节点：标为单节候选，不默认纳入。
3. 每条长链只输出第一节，子级不重复输出。
4. 输出时同时记录从总根/分支节点到真实入口的完整路径，避免将分支根误认为柔体入口。
5. 最终列表应优先包含具有连续子骨骼的链首；单节节点放入“待确认/排除候选”并说明原因。

## 示例结论

对于如下结构：

```text
Bone_qb_root
└─ Bone_qb_02
   ├─ Bone_qb_33_r
   │  ├─ Bone_qb_34_r -> ...
   │  └─ Bone_qb_41_r -> ...
   ├─ Bone_qb_12
   │  ├─ Bone_qb_13 -> ...
   │  └─ Bone_qb_20 -> ...
   └─ Bone_qb_01
```

应判定：

```text
排除为根/汇聚节点：Bone_qb_root、Bone_qb_02、Bone_qb_33_r、Bone_qb_12
长链柔体入口：Bone_qb_34_r、Bone_qb_41_r、Bone_qb_13、Bone_qb_20

```

## 避免的错误

- 不要把辅助骨骼树的总根直接作为柔体入口。
- 不要把拥有多个长分支的分支汇聚节点作为入口。
- 不要把单节骨骼自动当作柔体链。
- 不要只按“父级不是辅助骨骼”这一条规则输出；还必须判断该节点是否为根节点、汇聚节点、挂点或单节节点。
- 视觉截图只能用于核验位置和角色关联，不能替代完整层级分析。


## 常见错误

不要只看当前可见网格，也不要只检查已经发现的几条链。最容易漏掉的是编号较小、位于前面的一条辅助链，例如：

```text
Bone05 -> Bone06 -> Bone07 -> Bone08
```

必须先完整枚举并核对所有骨骼及其层级，再按“最上游真实辅助骨骼”确定链首；直接挂在 Biped 下只是常见情形之一，不能作为唯一筛选条件。对脱离 Biped 层级的链或经中间挂点/插槽连接的链，应纳入评估并记录入口路径；关联证据不足时列为待确认候选。

## MAXMCP_URL 与 3dsMax-MCP 服务器连接检查

执行场景审计前，必须先检查当前环境是否配置了 `MAXMCP_URL`，并通过该地址访问 3dsMax-MCP 服务器。不得猜测、硬编码或自行替换 MCP 地址，例如不得直接假设使用 `localhost`。

### 1. 检查环境变量

优先读取当前环境中的 `MAXMCP_URL`：

```bash
if [ -n "${MAXMCP_URL:-}" ]; then
  printf 'MAXMCP_URL is set: %s\\n' "$MAXMCP_URL"
else
  printf '%s\\n' 'MAXMCP_URL is not set'
fi
```

如果 `MAXMCP_URL` 未设置或为空：

- 不得猜测服务器地址；
- 不得直接访问 `127.0.0.1`、`localhost` 或其他默认地址；
- 应停止实际场景审计，并明确报告缺少 MCP 地址；
- 只有在用户补充配置或重新开启已配置 MCP 的会话后，才能继续。

### 2. 检查在线 Max 实例

使用已确认的 `MAXMCP_URL` 调用 3dsMax-MCP 的实例查询能力，优先使用 `list_instances` 或远程 Skill 提供的等效工具，确认服务器在线且存在可用的 3ds Max 实例。必须实际记录实例名称、在线状态和 busy 状态。

示例命令：

```bash
python /root/.claude/skills/3dsmax-mcp-remote/scripts/list_online_instances.py \\
  --url "$MAXMCP_URL"
```

若没有在线或空闲实例，不得猜测、虚构结果或擅自切换到未确认实例；应如实说明当前无法执行审计。**（边界：本规则仅适用于"实时审计"这类必须当场查询 Max 场景的操作；`submit_goskin_job` 队列提交不受此限——队列只需入队，无在线/空闲实例也照常提交，任务会排队等待实例释放，见 SKILL.md「GoSkin」节。）**

### 3. 选择并绑定目标实例

从实际返回的实例中选择目标 Max 实例，并使用实际返回的实例名称或 PID 进行绑定：

- 不得手写未查询到的实例名或 PID；
- 不得因选择失败而默默切换到另一个实例；
- 必须确认选择结果中的在线、获取租约或等效绑定状态；
- 若实例已被当前会话持有，应复用该实例，不重复排队获取。

### 4. 验证实际 MCP 工具面

连接后应确认服务器实际提供了审计所需能力，不得只依据文档假设工具一定存在。至少确认以下对应能力：

- 查询未隐藏对象，例如 `query_scene(action="unhidden_objects")`；
- 查询未隐藏网格和骨骼，例如 `get_unhidden_meshes_bones`；
- 查询对象层级，例如 `get_hierarchy`；
- 查询对象类型或属性，例如 `get_object_properties`；
- 必要时选择对象和捕获视口，例如 `select_objects`、`capture_viewport`。

如果服务器仅提供渐进式工具面，应根据实际工具列表使用 `list_toolsets`、`describe_toolset` 和 `call_tool` 发现并调用对应能力。遇到 `Unknown tool` 时，必须重新查询实际工具列表，不得持续猜测工具名。

### 5. 执行查询与视觉核验

完成环境、服务器和实例验证后，才可读取 `UnhiddenObjects`、骨骼层级和对象属性。需要视觉核验时：

- 使用已绑定或已确认的实例执行截图；
- 截图仅作交叉证据，不能替代层级和对象类型查询；
- 不得为了截图在 busy 实例上额外排队获取长时间租约；
- 视角切换失败或截图重复时，必须在结果中说明；
- 不得把未成功获得的视角描述为已完成核验。

### 6. 连接失败时的输出要求

如出现以下任一情况，必须停止场景结论输出并记录限制：

- `MAXMCP_URL` 未配置；
- MCP 服务器无法连接或返回错误；
- 没有在线或空闲 Max 实例；
- 工具面不包含必要的场景查询能力；
- 实例选择或绑定状态未确认；
- 层级查询不完整或无法确认对象类型。

连接失败时只能报告检查状态和失败原因，不能根据截图、文件名、历史结果或经验猜测当前场景的骨骼列表。
